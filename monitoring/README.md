# Monitoring

Ready-to-use Prometheus + Grafana setup for the NIXI SBC.

The SBC exposes Prometheus metrics at `GET /metrics` on its management API
(behind the bearer token; the `[metrics]` TOML block is not used). All
series are prefixed `sbc_` — calls, SIP traffic (by method / by response
code), auth, anti-fraud (bans, IRSF destination blocks, per-user limits),
media (RTP/SRTP/transcoding), health (last-CDR age, RTP timeouts, send
failures), per-trunk series (`sbc_trunk_up`, `sbc_trunk_registered`,
`sbc_trunk_active_calls`, `sbc_trunk_calls_total{trunk,direction,outcome}`,
`sbc_trunk_enabled`, `sbc_trunk_available`, `sbc_trunk_unavailable_seconds`,
`sbc_trunk_consecutive_failures`), the config store (`sbc_store_available`,
`sbc_store_created_empty`,
`sbc_store_backups_enabled`, `sbc_store_backup_interval_seconds`,
`sbc_store_backup_last_success_timestamp_seconds`,
`sbc_store_backup_last_bytes`, `sbc_store_backup_failures_total`), reloads
(`sbc_config_reloads_total{result}`, `sbc_config_last_reload_timestamp_seconds`),
listener certificates (`sbc_tls_cert_expiry_timestamp_seconds{listener,bind}`),
the CDR writer (`sbc_cdr_write_errors_total{stage}`, `sbc_cdr_queue_length`,
`sbc_cdrs_written_total`, `sbc_cdrs_purged_total`), the log writer
(`sbc_log_dropped_lines_total`) and the histograms
`sbc_call_setup_seconds` / `sbc_call_duration_seconds`.

## Prometheus

```yaml
# prometheus/prometheus-sbc.yml — add this scrape job to your prometheus.yml
scrape_configs:
  - job_name: 'nixi-sbc'
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials: 'YOUR_API_TOKEN'
    static_configs:
      - targets: ['127.0.0.1:8080']
```

Optional alerting rules are in `prometheus/alert_rules.yml`: `SBCDown`,
`SBCCdrsStale`, `SBCRtpTimeouts`, `SBCSessionTimer422Retries`,
`SBCSipSendFailures`, `SBCTrunkDown`, `SBCTrunkRegistrationFailing`,
`SBCTrunkAsrLow`, `SBCTrunkUnavailable`, `SBCStoreUnavailable`,
`SBCStoreBackupStale`, `SBCStoreBackupFailed`, `SBCCertExpiringSoon`,
`SBCCertExpired`, `SBCConfigReloadFailed`, `SBCCdrWriteErrors`,
`SBCCdrQueueBacklog`, `SBCLogLinesDropped`, `SBCAuthFailureSpike`.
Validate with `promtool check rules prometheus/alert_rules.yml`.

## Grafana

1. Copy the datasource provider to Grafana:
   `grafana/provisioning-datasource.yaml → /etc/grafana/provisioning/datasources/`
   (or use your existing Prometheus datasource — then set its UID in the
   dashboard, see below).
2. Copy the dashboard provider:
   `grafana/provisioning-dashboards.yaml → /etc/grafana/provisioning/dashboards/`
3. Copy the dashboard JSON to the provider's `path`:
   `grafana/dashboards/sbc-overview.json → /var/lib/grafana/dashboards/`
4. `systemctl restart grafana-server` — the dashboard appears in the **SBC**
   folder as **NIXI SBC — Overview**.

### Datasource UID

The dashboard references the Prometheus datasource by UID
(`efdqq22ymisqod` — the value used by the provided datasource file). If you
point the dashboard at an existing datasource with a different UID, either
set that UID in `provisioning-datasource.yaml`, or replace the `uid` fields
in `dashboards/sbc-overview.json`.

### Regenerating the dashboard

The dashboard JSON is generated by `grafana/dashboards/generate.py` (pure
Python, no deps). Edit the panel definitions there and run:

```bash
python3 grafana/dashboards/generate.py > grafana/dashboards/sbc-overview.json
```
